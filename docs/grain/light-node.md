# Лайт-нода GRAIN

## Что это

`CDatabaseLiteNode` — нода, которая **не исполняет** транзакции/query, а только читает гранулы:
недостающие докачивает с полной ноды по HTTP и кэширует в локальном RocksDB.

```
getGranule(addr):
    RocksDB (локальный кэш) → hit? вернуть
                              miss → GET полная-нода /granule?addr=<hex>
                                     → положить в кэш → вернуть
write/erase: только локально (RocksDB)
```

Полная нода отдаёт гранулы через `GET /granule?addr=<hex>` (тело — base16 `body`). См. `docs/http.md`.

## Доверие (трустлесс)

Нода отдаёт гранулу по адресу; **клиент проверяет её хэш против корня Merkle**, который подписан
валидаторами (BLS-агрегат `agg_diff_sig`). То есть клиент доверяет не серверу, а криптографии:
подписанный root + Merkle-доказательство пути гранулы.

> Если прошлый блок подписан всеми валидаторами — этого **достаточно для доверия клиенту**:
> любая гранула состояния проверяется против подписанного root. Подделка гранулы = расхождение
> с подписанным root.

## Что НЕ решено (честно)

- Подпись доказывает «этот root подписан валидаторами», но **не** «этот root — финальная каноничная цепь».
  На нефинализированной вилке валидаторы могли подписать и другой root.
- Нужен явный маркер **финализации** (или несколько подтверждений), чтобы клиент отличал
  «подписано всеми» от «подписано, но это вилка».
- Лайт-нода защищена от **подделки**, но не от **следования нефинализированной ветке**.

## Режимы работы

| Режим | Что делает | Трафик |
|-------|-----------|--------|
| Полная нода | исполняет tx + query, хранит весь стейт | — |
| Лайт-нода (кеш) | не исполняет, читает гранулы по HTTP, кэширует | по запросу |
| Клиент-вычисления | нода отдаёт **сырые гранулы по хэшам**, query считает **клиент** | меньше (без исполнения) |
| Старое состояние | клиент держит гранулы на прошлую высоту, читает по хэшам | по запросу |

Перенос вычислений query в клиента — это экономия трафика и уход от исполнения запросов на ноде:
нода становится «хранилищем гранул», а не вычислителем.

## Запросы по хэшам гранул

- `GET /granule?addr=<hex>` — гранула по адресу (путь от корня).
- `GET /grain/{type}/{id}?hash=<expected_hash>` — гранула + ожидаемый хэш (клиент сверяет и кэширует).
- Ключ гранулы — это её детерминированный путь от корня; зная путь, можно запросить и проверить хэш.

## Вложенность гранул (адресация)

Плоский API (старый):
```js
getGranule("key")
createGranule("key", value, ttl)
setGranule("key", value)
```

Иерархический API (новый, `JsiStorage` — вложенный узел):
```js
let root = get_granule("path")          // JsiStorage
let child = root.get_granule("sub")     // вложенный узел
create_granule("a/b/c", ttl)            // дерево внутри контракта
```

Адрес гранулы — её путь от корня (ключ RocksDB). Вложенность — дерево `JsiStorage` внутри контракта
под базовым префиксом контракта: изоляция между контрактами, нет коллизий ключей.
