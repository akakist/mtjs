# Консенсус и хранение GRAIN

GRAIN — детерминированный конечный автомат. Всё состояние сети — одно гранулированное Merkle-дерево.
Каждый блок — переход состояния. **Предмет консенсуса — не сам блок, а post-block состояние** (корень Merkle).

## Стадии блока

Каждый раунд проходит по цепочке (все стадии на алармах, без re-broadcast):

```
Ping → GetTx → ValidateBlock → BlockDiffValidate → BlockAccepted
```

1. **Ping** — лидер рассылает `PingREQ` (с `HeartBeatREQ` = prev_root_hash, new_epoch, node_leader).
   Нода отвечает `PingRSP` и **BLS-подписывает хэш hb** (`sig`). Лидер собирает ответы → **alive-сет**.
2. **GetTx** — лидер (`current_leader()`) собирает транзакции `GetTxREQ`/`GetTxRSP`.
3. **ValidateBlock** — лидер собирает блок (`do_start_block`) и рассылает `ValidateBlockREQ`.
4. **BlockDiffValidate** — валидаторы выполняют блок (`execute_block`), вычисляют дифф состояния
   и подписывают его BLS (`BlockDiffValidateRSP`).
5. **BlockAccepted** — лидер агрегирует подписи: `agg_diff_sig` + `node_diff_validators` (валидация диффа)
   и `agg_alive_sig` + `alive_validators` (подписанный alive-сет пинга) → `BlockAccepted2REQ`.

## Живость нод (alive-сет, а не счётчики)

- **Пинг объективен**: ответ подписан BLS, агрегат (`agg_alive_sig`) лежит в блоке и проверяется.
  Цензура пинга ограничена кворумом — выбросить можно только меньшинство.
- В `execute_block` для нод из alive-сета прошлого блока обновляется:
  - `activity._update_time` — источник для **физического удаления** (GC по TTL);
  - `node.last_update` — **кэш на bc_node**, чтобы не читать гранулу activity при фильтре vne.
- **Состав vne**: `enabled && node_active`, где
  ```
  node_active(n):
      если n.last_update == 0 → true          // sentinel «ещё не пинговал» (генезис/новая нода)
      иначе (block_ts - n.last_update) <= TTL // 60с
  ```
  `last_update == 0` — уникальный случай (как `ttl == 0` = вечный): генезис создаётся с `time0 = 0`,
  а старт нод у всех разный, поэтому `time(NULL)` в генезисе использовать нельзя.
- Ручной `node_enable`/`node_disable` — отдельный флаг `enabled` (опционально).

## Выбор лидера

- `current_leader() = committee[slot % size]`, где `slot = (now - lastBlockTime) / SLOT_MKS`
  (правый край слота — «мёртвая зона», лидера нет).
- `current_leader()` нужен **только для GetTx**. После него слот может уехать, но блок доделывается
  со «замороженным» лидером из `cli.node_leader`; по аларму `TIMER_BLOCK_EXPIRED` кэш сбрасывается.
- Комитет (`committee_vne`) — подмножество vne (строгий фильтр «уже пинговал» + stake, затем релакс-фолбэк).

## Кворумы

- Пинг: `is_PingRSP_m_quorum` — доля от полного включённого стейка.
- Дифф: `is_BlockDiffValidateRSP_m_quorum`.

## Структура хранения

- **Гранула** — атомарный фрагмент состояния. `path → value` в RocksDB; `path` — детерминированный
  путь от корня (это и есть ключ). Лист, к которому обратились, помечается dirty; после блока
  пересчитываются только изменённые листья и их родители вверх до корня.
- **Адресация контракта**: у контракта есть базовый адрес, все его данные лежат под этим префиксом
  (изоляция, нет коллизий).
- **granular_map** — дерево с ветвлением по base-62 (62/62²/62³…), для сотен миллионов записей.
  Нет MVCC, WAL, VACUUM, индексов — детерминированная структура, O(log N) обновление.
- **activity + TTL**: каждая гранула/нода/контракт имеет `bc_activity` (`_update_time` + `ttl`).
  Нет активности дольше TTL → GC физически удаляет. Явного удаления контрактом нет —
  правило «выставил TTL, нет активности → удалилось само». Удаление (тумбстоун) + пересоздание —
  через компакцию.

## Преимущества

- Обновление только изменённых листьев и их родителей — `O(log N)`, без пересборки всего дерева.
- Детерминизм: одни и те же транзакции → один и тот же root (предмет консенсуса).
- Нет MVCC/WAL/VACUUM/индексов — проще и дешевле эксплуатация.
- Подписанный alive-сет в блоке — объективная живость, а не «взгляд лидера».
- Чтения шардируются (любая нода), запись — через консенсус (CQRS).

## Нерешённое / на что смотреть

- Раскол `current_leader()` при расхождении `prev_root_hash`/`lastBlockTime` у нод (ловим трассой `MTJS_LEADER_TRACE`).
- Точная синхронизация слотов между нодами (зависит от wall-clock `now`).
- Сортировка дерева рассылки по `last_update` (отложена).
